# Design Workflow

## Purpose

Use this document to guide the project from context to design delivery.

## Phase 0: Kickstart

Goal: define the problem space, constraints, and success criteria before design work starts.

Checklist:

- [ ] Product/module confirmed
- [ ] Menu or feature area confirmed
- [ ] Work type confirmed: new feature / improvement / redesign / UX fix
- [ ] Problem statement drafted
- [ ] Business goal aligned with design goal
- [ ] Target user identified
- [ ] Success metric defined
- [ ] Constraints documented

Primary files:

- `context/context.md`
- `context/project-brief.md`
- `context/problem-framing.md`

## Phase 1: Discover

Goal: gather enough evidence to understand the user problem.

Inputs:

- User interviews or stakeholder notes
- Competitive or benchmark review
- Existing analytics, support notes, or customer examples
- Current-state screenshots or Figma references

Checkpoint:

- Problem statement is supported by evidence or clearly marked as an assumption.

## Phase 2: Define

Goal: turn findings into clear design requirements.

Deliverables:

- Persona or user segment
- Jobs to be done
- User flow
- Journey map
- PRD or requirements
- Information architecture, if navigation is involved

Checkpoint:

- The user, job, flow, problem, and requirements are specific enough to design from.

## Phase 3: Develop

Goal: explore and select the right solution direction.

Methods:

- Concept options
- Wireframes
- Figma Make / Stitch prompts
- Design principles filter
- Feature prioritization

Checkpoint:

- The selected concept covers the main happy path and at least one error or edge state.

## Phase 4: Test

Goal: validate the most important assumption before handoff.

Testing options:

- Quick stakeholder walkthrough
- Usability test with 5 users
- Prototype task test
- Design critique / heuristic review

Metrics:

- Task completion
- Time on task
- Error rate
- Confidence / satisfaction
- Critical usability issues

Checkpoint:

- Critical issues are documented with severity and recommended action.

## Phase 5: Deliver

Goal: prepare design documentation for stakeholders or engineering.

Handoff checklist:

- [ ] Screens documented
- [ ] States covered: default, hover, focus, active, disabled, loading, empty, error
- [ ] Interaction specs documented
- [ ] Edge cases covered
- [ ] Accessibility notes included
- [ ] Open questions tracked
- [ ] Figma links added

Checkpoint:

- Engineering or stakeholders can understand the design without guessing intent or behavior.
